# Этап 0. Что реально отдаёт Checko API

Проверено 06.11.2026 живыми запросами к `https://api.checko.ru/v2/` с тестовым ключом (бесплатный тариф, баланс 0 ₽). Использовано 24 запроса. Тестовые компании: ПАО Сбербанк (7707083893), ООО «Яндекс» (7736207543), ООО «Своя пекарня» (5256088074), физлицо по ИНН руководителя.

## Матрица методов

| Метод | Параметры | Что приходит | Для чего в ТЗ |
|---|---|---|---|
| `company` | `inn` или `ogrn` | Полная карточка ЮЛ: статус, регион, ОКВЭД, уставный капитал, руководители и учредители (с ИНН, долей и датой записи), связанные компании (`СвязУчред`, `СвязУпрОрг`), филиалы, лицензии, контакты, налоги и спецрежимы, категория МСП (`РМСП`), полученная господдержка (`ПоддержМСП`), численность (`СЧР`), флаги (банкротство ЕФРСБ, недобросовестный поставщик, массовость, санкции), дата выписки (`ДатаВып`) | Карточка, госпрограммы, снимки для мониторинга |
| `timeline` | `inn` | Список событий с датой и текстом: регистрация, смена статуса, вход и выход из учредителей других компаний, сдача отчётности и т. п. (у «Яндекса» 127 событий, последнее 21.09.2026) | **Основа мониторинга** |
| `person` | `inn` физлица | Компании, где человек руководитель или учредитель, его ИП, флаги (массовость, санкции, ЕФРСБ) | Новые регистрации у учредителей и директоров |
| `entrepreneur` | `inn` ИП | Карточка ИП (на тестовом ИНН ЮЛ правильно ответил «не найдено») | ИП в портфеле |
| `finances` | `inn` | Бухотчётность по годам (у «Яндекса» 2011–2024) с кодами строк форм 1–4: баланс (1xxx), прибыли и убытки (2xxx), капитал (3xxx), движение денег (4xxx). Плюс ссылки на PDF в ГИР БО | Финанализ |
| `legal-cases` | `inn` | Арбитражные дела: номер, роль, сумма иска, исход, ссылка на kad.arbitr.ru | Риски |
| `enforcements` | `inn` | Исполнительные производства ФССП: количество, суммы, остаток долга | Риски |
| `fedresurs` | `inn` | Сообщения Федресурса (аудит, залоги и т. п.) | Риски, события |
| `bankruptcy-messages` | `inn` | Сообщения о банкротстве | Риски, события |
| `inspections` | `inn` | Проверки контролирующих органов | Риски |
| `contracts` | `inn` + `law` (44/223) | Госконтракты | Позже |
| `search` | `by`, `obj`, `query` | Поиск компаний по названию с пагинацией | Подсказки при вводе |

Методов `changes`, `events` или `history` нет. Готового потока «изменения с даты X» API не даёт.

## Выводы для мониторинга

1. **Изменения в ЕГРЮЛ (`REGISTRY_CHANGE`).** Можно делать двумя способами: брать новые записи из `timeline` и сравнивать ежедневный снимок `company` (руководитель, учредители, адрес, статус, ОКВЭД). Лучше использовать оба: timeline даёт готовый текст события, снимок ловит то, чего нет в timeline.
2. **Новые связанные компании (`NEW_RELATED_ENTITY`).** В `timeline` есть «X становится учредителем Y» с ОГРН новой компании. Новые регистрации у учредителей и директоров видны через `person`: для каждого ИНН из `Руковод` и `Учред` храним список его компаний и ИП и сравниваем.
3. **Новые ИП (`NEW_IP_REGISTRATION`).** Технически поле `ИП` в `person` есть. По ТЗ включаем только после юридической проверки.
4. **Цена мониторинга.** Каждый успешный вызов списывает запрос (счётчик `today_request_count` в ответе), а ошибочные вызовы не списывают. На один ИНН в день уходит примерно 2 запроса (`company` и `timeline`) плюс по одному на каждого учредителя или директора. Значит, `person` стоит дёргать реже, например раз в неделю, или только когда изменился состав.

## Выводы для госпрограмм

Для правил отбора из API доступны: категория МСП и дата включения в реестр, численность, регион, ОКВЭД (основной и дополнительные), спецрежим налогообложения, уплаченные налоги, история полученной поддержки, а также стоп-факторы (банкротство, недобросовестный поставщик, санкции, массовость). Для первого набора программ этого хватает.

## Выводы для финанализа

- Есть формы 1–4 за 10+ лет, этого достаточно для метрик за 2–3 года.
- **Амортизации нет.** Строк пояснений (5640 и т. п.) в данных нет, поэтому EBITDA, как и предусмотрено в ТЗ, показываем как `N/A`, либо даём оценку с явной пометкой.
- **У банков отчётности нет.** У Сбербанка `finances` пустой, потому что банки не сдают РСБУ в ГИР БО. Для банков и страховых нужен отдельный источник или честное «нет данных».
- Суммы приходят в рублях, а не в тысячах.

## Ответы на открытые вопросы (06.11.2026)

1. **Дневной лимит бесплатного тарифа: 100 запросов.** Антону этого достаточно. При ~2 запросах на ИНН в день это примерно 30–40 компаний с ежедневной проверкой, а проверку учредителей через `person` делаем реже.
2. **Оферта Checko разрешает** использовать ключ через сторонний сервис (подтвердил Антон).
3. Поиск по ИНН физлица (`person`) затрагивает персональные данные, это остаётся пунктом юридической проверки.
